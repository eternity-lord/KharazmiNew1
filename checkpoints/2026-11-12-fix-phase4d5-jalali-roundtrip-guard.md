# P4d-5 — `jalaliToGregorian` پورتِ ناقصِ سرور بود: گاردِ رفت‌وبرگشتی نداشت

## ۱) باگ

`JalaliUtils.jalaliToGregorian` کامنت داشت «Exact port of server
jalali_to_gregorian()» — ولی **پورتِ ناقص** بود. سرور
(`KHarazmi_Server/today_summary.py:86`) در پایانِ تابع یک گاردِ رفت‌وبرگشتی دارد:

```python
result = datetime.date(gy, gm, gd)
if gregorian_to_jalali(result) != original:
    raise ValueError("Invalid Jalali date")
return result
```

پورتِ Kotlin این گارد را نداشت؛ فقط `require(jm in 1..12 && jd in 1..31)` را می‌سنجید
و بعد حلقهٔ `while (gm <= 12 && gd > monthDays[gm])` روزِ اضافی را **بی‌صدا به ماهِ
بعد سُرسره می‌کرد**. نتیجه: تاریخِ محال به‌جایِ رد شدن، به تاریخِ دیگری تبدیل می‌شد:

| ورودی | کلاینت (پیش ازِ رفع) | سرور | |
|---|---|---|---|
| `1404/07/30` | ۲۰۲۵-۱۰-۲۲ | ۲۰۲۵-۱۰-۲۲ | یکسان |
| `1404/07/31` (مهر ۳۰ روز دارد) | **۲۰۲۵-۱۰-۲۳** | **رد می‌کند** | ❌ واگرا |
| `1404/11/31` | **۲۰۲۶-۰۲-۲۰** | **رد می‌کند** | ❌ واگرا |
| `1404/12/30` (۱۴۰۴ کبیسه نیست) | **۲۰۲۶-۰۳-۲۱** | **رد می‌کند** | ❌ واگرا |
| `1403/12/30` (۱۴۰۳ کبیسه است) | ۲۰۲۵-۰۳-۲۰ | ۲۰۲۵-۰۳-۲۰ | یکسان |

ظریف‌ترین حالت، اسفند است: اعتبارِ روزِ ۳۰ به **کبیسه‌بودنِ سال** وابسته است و هیچ
`require` ساده‌ای نمی‌تواند بگیردش — فقط گاردِ رفت‌وبرگشتی می‌گیرد.

### اندازه‌گیریِ واگرایی (نه حدس)
تابعِ **واقعیِ سرور** با `exec` در Python بارگذاری شد (نه بازنویسیِ چشمی) و رویِ
شبکهٔ کاملِ ورودی‌هایِ قابلِ رسیدن اجرا شد. دامنه از خودِ پارسر گرفته شده:
`DATE_RE` چهار رقم می‌گیرد و heuristicِ «سال < ۱۷۰۰ ⇒ جلالی» یعنی `jy ∈ [1000, 1699]`.

```

  کرش در نسخهٔ اصلاح‌شده:          0

```

## ۲) شعاعِ اثر در برنامه

```
jalaliToGregorian  ← parseProjectDate (خواندنِ تاریخِ ذخیره‌شده؛ «null on garbage, never throws»)
                   ← isBeforeToday    ← StudentProfileActivity.kt:1067

```
یعنی **پرچمِ «سررسیدِ گذشته»ی قسط**. و `StudentProfileFormat.isValidJalaliDate`
(که در PR #18 درست شد) فقط **قالب** را می‌سنجد (`^\d{4}/\d{2}/\d{2}$`)، پس
`۱۴۰۴/۰۷/۳۱` از آن گیت رد می‌شود و تا اینجا می‌آمد.

یک شاهدِ درونیِ دیگر: در **همان تابعِ** `parseProjectDate`، شاخهٔ میلادی
`isLenient = false` می‌گذارد و با `time` اعتبار را اجبار می‌کند («throws on
impossible dates») ولی شاخهٔ جلالی هیچ اعتبارسنجیِ تقویمی نداشت ⇒ ناسازگاریِ
دو شاخهٔ یک تابع.

هیچ تستی این رفتار را پین نکرده بود (`git grep jalaliToGregorian|isBeforeToday`
رویِ هر دو پوشهٔ تست ⇒ خالی)، پس اصلاح بدونِ دست‌زدن به کورپسِ تست ممکن بود.

## ۳) رفع

سه خط، دقیقاً معادلِ سرور — `require` همان `IllegalArgumentException` است که
`catch (e: Exception) → null` در `parseProjectDate` می‌گیردش، هم‌نوع با `ValueError`
سرور. `gregorianToJalali` از پیش در همان فایل بود (L112).

```kotlin
require(gm in 1..12 && gregorianToJalali(gy, gm, gd) == Triple(jyIn, jm, jd)) {
    "Invalid Jalali date"
}
return GregorianCalendar(gy, gm - 1, gd)
```

**چرا `gm in 1..12` اول می‌آید:** اگر روزِ محال از دوازده ماه سرریز کند، `gm` برابرِ
۱۳ می‌شود و `gregorianToJalali(gy, 13, gd)` به `cumulativeMonthDays[12]` می‌خورد
⇒ `ArrayIndexOutOfBoundsException` به‌جایِ یک خطایِ تمیز. `require` با `&&`
کوتاه‌مدار جلویش را می‌گیرد. رویِ همان شبکهٔ ۲۶۰٬۴۰۰ حالتی سنجیده شد که `gm=13`
هرگز رخ نمی‌دهد، ولی این پیش‌شرط هزینه‌ای ندارد و دامِ آینده را می‌بندد.

## ۶) دام‌هایِ محیطیِ این اسلایس

1. **ناسازگاریِ overlay، نه flapِ لحظه‌ای.** دیدِ فایل‌سیستم بینِ syscallها و بینِ
   فرآیندها یکسان نیست و می‌تواند **دقیقه‌ها** بماند:
   - `ls -la` فایلِ ۷۰۰ بایتی را نشان می‌داد و `test -e` = YES، ولی `cat` و
     `open()` با `ENOENT` شکست می‌خوردند (۴۰ تلاشِ پیاپی) — و چند ثانیه بعد همان
     `cat` در نخستین تلاش موفق شد.
   - برعکسش هم دیده شد: `opendir` رویِ `Kharazmi_Server/tests` سالم بود (۸۲ ورودی)
     ولی `stat` رویِ **خودِ پوشه** خطا می‌داد؛ و `[ -f FILE ]` موفق بود در حالی که
     `md5sum` همان مسیر در همان ثانیه شکست خورد.
   - `git show HEAD:<path>` و `git ls-files -s <path>` هم برایِ **یک مسیرِ خاص**
     گاهی `fatal: does not exist in 'HEAD'` یا sha خالی برمی‌گردانند، در حالی که
     `git ls-tree -r HEAD` همان مسیر را کامل فهرست می‌کند ⇒ حتی آبجکت‌استور هم
     از این ناسازگاری مصون نیست.
2. **`d41d8cd98f00b204e9800998ecf8427e` یعنی md5ِ رشتهٔ خالی.** وقتی `cat` در
   لوله بی‌صدا چیزی نمی‌خواند، `md5sum` یک مقدارِ «واقع‌نما» چاپ می‌کند که با
   بیس‌لاین فرق دارد. هر md5ِ لوله‌ای باید در برابرِ این مقدارِ خاص نگهبان شود،
   وگرنه «تغییر کرد» نتیجه می‌گیریم در حالی که «نخواند».
3. **`&&` در زنجیرهٔ نصب، کلِ نصب را نیمه‌کاره گذاشت.** چون یک فایلِ requirements
   در آن لحظه دیده نمی‌شد، `pip install -r … && pip install -r … && pip install pytest`
   در گامِ دوم متوقف شد و pytest هرگز نصب نشد.
4. **«venv آماده است» را با `ls .venv/bin/python` سنجیدم و غلط بود.** وجودِ مفسر
   یعنی `python3 -m venv` تمام شده، نه اینکه پکیج‌ها نصب شده باشند. دو گیت با
   `No module named pytest` بی‌صدا خالی شدند و من تقریباً آن را به flap نسبت دادم.
   معیارِ درست: `python -m pytest --version` و importِ تک‌تکِ ماژول‌ها.
5. **لاگِ خالی یعنی «نگاه کن»، نه «رد شو».** هر دو گیت exit=0 و لاگِ ۶۵ بایتی
   داشتند؛ `grep -c passed` صفر شد و فقط `cat` لاگ علت را نشان داد.
6. **برایِ خواندنِ محتوایِ فایلی که دیده نمی‌شود، از مسیر نرو:** `git cat-file blob`
   با shaِ گرفته‌شده از `git ls-tree` (که پایدارتر از `ls-files -s` بود) — و اگر
   آن هم نشد، حلقهٔ تلاشِ کوتاه‌فاصله (۱ ثانیه) مؤثرتر از فاصلهٔ بلند بود.
